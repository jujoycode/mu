# 04. 로드맵

## P0 — 코어 루프 (1–2주) ← 현재 단계

- 스트리밍 LLM 클라이언트 (Anthropic 단일 프로바이더)
- 툴콜 루프 + 기본 도구 4개 (read / write / edit / bash)
- 단일 세션, 최소 REPL

**완료 조건**: 실제 팀 레포에서 작은 버그픽스 하나를
mu가 사람 개입 없이 diff까지 뽑아내면 클리어.

## P1 — 신뢰성 + remote_exec

- 세션 저장/재개 (messages 배열 JSON 덤프)
- bash 안전장치 (위험 명령 권한 게이트)
- 재시도·에러 처리, 토큰/비용 추적
- **`remote_exec` 툴** (설계: docs/05) — 원래 P2였으나 앞당김

> 조정 이력: remote_exec P2 → P1.
> 이유: 매일 아픈 페인포인트라 초기 체감 가치가 가장 큼.

## P2 — 스킬 시스템 (본체)

- git 기반 팀 스킬 레포 + lazy loading (설계: docs/05)
- `load_skill` 툴, grep 기반 지식 검색 툴
- 사내 API 호출 툴, 배포·테스트 파이프라인 연동 등 "팀 전용" 도구 확충
- 팀 코드 컨벤션이 반영된 시스템 프롬프트 정비

## P3 — 도그푸딩 (폴리시 대신)

내부용이므로 TUI 폴리시·패키징·문서화보다 **실사용 확산**이 우선.

- 2주차부터 제작자 본인이 매일 사용
- P2 시점에 팀원 투입
- 지표 측정 시작: 주간 실사용 인원, mu로 완수한 태스크 수

## 통과 기준 요약

| 단계 | 게이트 |
|------|--------|
| P0 → P1 | 실레포 버그픽스 1건 무개입 완수 |
| P1 → P2 | remote_exec로 dev 서버 작업 1건 완수 + 세션 재개 동작 |
| P2 → P3 | 팀원 1명 이상이 스킬 레포 pull 받아 실사용 |
