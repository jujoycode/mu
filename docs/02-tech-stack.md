# 02. 기술 스택 결정

## 결정: TypeScript + Bun

후보는 TS / Go / Rust (셋 다 구현 가능한 상태에서 비교).

### TS를 선택한 근거

1. **Harness는 I/O-bound** — 병목은 LLM 응답 대기지 harness 코드가 아님.
   언어 성능은 이 제품에서 사실상 무의미
2. **참조 구현과의 거리** — Pi가 MIT 라이선스 TS. 아키텍처를 코드 레벨로 참고 가능
3. **생태계** — Anthropic SDK, MCP SDK 모두 TS가 1급 시민.
   툴 스키마·스트리밍 파싱·스킬 메타데이터가 전부 JSON/markdown 중심이라 마찰 최소
4. **배포 격차 해소** — `bun build --compile`로 단일 실행파일 생성 가능.
   내부용은 어차피 `bun link` / `@team/mu` 스코프 패키지면 충분
5. **지속 가능성** — "3주 뒤에도 만지고 싶은 언어" 기준에서 최고 점수

### 대안 평가

| 언어 | 평가 | 비고 |
|------|------|------|
| Go | 근소한 2위 | 단일 바이너리, Bubble Tea(최강 TUI 생태계), 레퍼런스로 Charm의 Crush 존재. 인프라 성향이면 정당한 선택 |
| Rust | 이번엔 보류 | 병목이 성능이 아니라 "완성되느냐"인 제품. tokio+스트리밍+툴 트레잇 조합은 초기 속도를 깎음. Rust 학습 자체가 주목적일 때만 정당 |

참고: OpenAI Codex CLI도 TS로 먼저 검증한 뒤에야 Rust로 재작성했다.
성능/배포 통증이 **실재할 때** 재작성해도 늦지 않다.

## 언어 중립적 설계 원칙

언어 의존도를 낮추는 두 가지 설계 결정 (언어를 바꿔도 아키텍처가 살아남도록):

1. **스킬 = 데이터, 코드 아님** — 스킬은 markdown(+선택적 스크립트)으로 정의.
   harness 언어와 무관하게 작성·배포 가능
2. **SSH = 시스템 `ssh` 셸아웃** — 라이브러리 임베딩 금지.
   `~/.ssh/config`, ssh-agent, ProxyJump를 공짜로 상속받고 언어 의존성 제거

## 런타임/배포

- 런타임: Bun (TS 직접 실행, 빌드 스텝 없음)
- 팀 배포: git clone + `bun install` + `bun link` → `mu` 명령 즉시 사용
- npm: `@team/mu` 스코프 (필요 시)
