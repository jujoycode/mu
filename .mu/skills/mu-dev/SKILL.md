# mu 개발 스킬

mu 저장소에서 작업할 때 따르는 절차. (팀 스킬 레포의 예시이자 도그푸딩용 실제 스킬.)

## 변경 전 확인

- 아키텍처 요점과 절대 규칙은 `CLAUDE.md`에, 설계 배경은 `docs/`에 있다. 관련 설계를 먼저 읽는다.
- `src/agent.ts`는 코어 루프다 — **~150줄 유지**가 목표. 여기에 기능을 더하기 전에
  "툴이나 확장으로 가능한가?"를 자문한다.

## 검증 (변경 후 반드시)

```
bunx tsc --noEmit    # 타입 체크 — 반드시 clean
bun test             # 전체 테스트 — 반드시 통과
```

## 규약

- 툴 실패는 throw하지 말고 `{ content, isError: true }`로 반환한다. 실패는 정보다.
- `messages` 배열이 유일한 상태다. 그 밖의 상태를 만들지 않는다.
- 프롬프트는 `MU.md`에서 수정한다 (코드에 하드코딩 금지). 이 파일은 개발용 `CLAUDE.md`와 다르다.
- SSH 키·시크릿은 코드/컨텍스트/로그에 절대 넣지 않는다. 모델은 호스트 별칭만 본다.
- 설계 결정을 바꾸면 `docs/`의 해당 문서를 같은 커밋에서 업데이트한다.

## 커밋

- 작은 단위로 명확한 메시지. 무엇을·왜 바꿨는지 본문에 남긴다.
